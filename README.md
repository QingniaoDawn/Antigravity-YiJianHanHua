# Antigravity 一键汉化

> Google Antigravity（Agentic IDE）**Windows / macOS** 一键汉化工具
> **19956 翻译单元 · 双击即用 · 汉化零联网（唯一联网：手动检查更新）· 永久免费**

---

## 这是什么

[Antigravity](https://antigravity.google) 是 Google 出品的智能体编程 IDE，界面默认英文。
本工具把它完整变成简体中文——不需要懂命令行，不需要会编程：

- **双击 `一键汉化.bat`（Windows）/ `一键汉化.command`（macOS）**，按数字选功能
- 官方更新后界面变回英文？**再双击一次，重新汉化就好**
- 想换回英文原版？**一键还原**，还原结果与官方原版字节级一致

## 先看你是什么系统

| 你的系统 | 用哪个 | 启动方式 |
|---|---|---|
| **Windows** | 仓库根目录的 `一键汉化.bat` | 双击即用 |
| **macOS** | [`mac/`](mac/) 目录 | 右键 `一键汉化.command` → 选择「打开」 |

两个平台共用同一套引擎与词典（词条量、覆盖范围、备份策略完全一致），
`localize.py` 会自动识别当前系统走对应分支。

> macOS 用户请看 **[mac/README.md](mac/README.md)**，里面讲清了代码签名这件事，
> 以及遇到「应用已损坏」怎么办。

## 使用方法

### 环境要求

**Windows：**

- Windows + 已安装 Antigravity（默认安装路径自动识别，装在别处可用 `--path` 指定）
- [Python](https://www.python.org/downloads/) 3.8+（安装时勾选 **Add Python to PATH**）
- [Node.js](https://nodejs.org) 18+（解包/打包安装包用）

**macOS**（详见 [mac/README.md](mac/README.md)）：

- macOS 12+ + 已安装 Antigravity
- Python 3.8+（`brew install python`）
- Node.js 18+（`brew install node`）
- **Xcode 命令行工具**（`xcode-select --install`）——提供 `codesign`/`xattr`，
  没有它汉化后 App 会打不开，主程序会在汉化前明确报错

### 操作菜单

Windows 双击 `一键汉化.bat`，macOS 右键 `一键汉化.command` →「打开」：

| 选项 | 功能 |
|---|---|
| `1` 一键汉化 | 自动关进程 → 备份原版 → 注入汉化 → 校验 → 部署（macOS 追加自动重签名） |
| `2` 恢复官方英文原版 | 用备份一键还原，字节级与官方一致 |
| `3` 查看状态 | 当前是否已汉化、备份是否完好（macOS 追加签名健康度） |
| `4` AI 回复中文化 | 写入一条全局规则，让 **AI 自己用中文回答**（思考过程仍英文，可随时关闭） |
| `5` 检查更新 | 查 GitHub 上有没有新版本；可选下载到桌面，**不会自动替换你现有的文件** |

也可以命令行调用：`python localize.py apply / restore / status / chinese-output / update`（macOS 用 `python3`）

### 关于「检查更新」

- **默认不联网**：只有你主动选 `5`（或运行 `update`）时才会发一次请求，
  其余所有功能（汉化、还原、查看状态、AI 中文化）全程零网络行为。
- **只查不换**：请求的是 GitHub Release 元数据（版本号、更新说明、下载链接），
  不下载执行任何远端代码。就算你选了下载，也只是把 zip 存到桌面，
  **解压和替换由你自己决定**，本工具绝不动你现有的文件。
- **下不动有退路**：可以选「只要下载链接」，自己用浏览器或下载工具下。
- **查不到不影响使用**：网络不通、被限流时只会提示一句，不会报错卡住。
- **带 SHA256 校验**：若该版本的 Release 附带了 `SHA256SUMS.txt`，下载后会自动比对，
  不一致会明确告警，让你知道文件可能不完整或被掉包。

> **想让 AI 的回复也是中文？** 选 `4`。界面汉化管不了 AI 生成的内容，
> 正确做法是加一条"用简体中文回复"的全局规则（脚本已内置该功能）。

### 官方更新后怎么办

Antigravity 官方更新后界面会变回英文——这是正常现象，不是坏了。
**再运行一次选项 `1` 重新汉化即可**，备份会自动升级为新版官方原版。

**可以连续操作**：每个操作做完会停一下让你看结果，按回车就回到主菜单，接着选下一项即可
（比如先「查看状态」再「一键汉化」，或者「汉化 → 恢复英文 → 再汉化」）。
窗口不会自己关掉；要关闭请点右上角的 ×，或者选 `0` 退出。
（macOS 上重签名也会一并重新完成）

界面翻译采用**运行时 DOM 文本匹配**，不修改官方界面文件本身。
因此官方更新不会破坏已有汉化，只可能新增少量未收录的新文案。

**v1.10 补漏（2026-10-30）**：上一版发出去后，把界面逐页扫了一遍（不是只扫打包文件，
而是把运行中的应用当审计对象，逐页读 DOM），补掉三类漏翻和两类引擎隐患：

1. **被图标切断的句子碎片**：提示卡里的 `in the top left.` / `menu)` 这类片段，
   因为中间夹着图标，整句永远匹配不上，于是永远显示英文（或半中半英）。
   这次按「前半句 + 图标 + 后半句」的实际渲染顺序分别给译文，拼起来才是通顺中文。
2. **扩展市场的分类与服务端文案**：7 个分类名与说明、11 张内置卡片说明、
   50 个合作方插件的完整介绍、页脚免责声明，全部补齐。
   插件**名称**保持英文原样（Browserbase、Stripe 这类产品名硬翻反而找不到东西），
   「See 18 more」改成「再显示 18 个」。
3. **模型选择器的公告**：`Notice` / `Unavailable` 徽章，以及悬停后的整段公告
   （含 `starting on November 2, 2026` 这种带日期的句子）——这类文案是服务端下发的，
   每次上线都可能变，所以走**动态规则**而不是死记硬背。

引擎这一轮补了两件事：

- **日期与时长归一**：译文里残留的 `November 2, 2026` 会变成 `2026年11月2日`，
  配额提示里的 `Resets in 3h54m47s` 会变成 `3小时54分47秒后重置`。
- **多词串的链接保护**：原来只保护「单个词 + 技术符号」，实测
  `See [go/jetski-agent-sidecars#trusted-locations](…)` 这种两段式串会把链接里的
  `jetski-agent` 替成 `jetski-智能体`，**点开会 404**。现在整串含 URL / 文件名 / 锚点时一律原样返回。

另外顺手修掉两个坑：

- **从 Electron 系终端启动会「假失败」**：VS Code / WorkBuddy 这类终端会给子进程带上
  `ELECTRON_RUN_AS_NODE=1`，Antigravity 继承后会被当成 Node 解释器——不弹窗、立刻退出 0。
  以前只在日志里报「启动失败」，现在启动前会主动剔除这个变量。
- **两条会把整段塞进短词的前缀规则**：它们让技能说明变成
  「中文半句 + 英文整段」的拼接怪，已删除，改用完整精确词条覆盖。

覆盖率（同一套 2466 条候选口径）：**2123 条 → 2164 条，86.1% → 87.8%**。
剩下 291 条全英文的都是内部开关名、代码常量、错误信息这类不该翻的内容。

主词典由 19363 条增至 **19460 条**（词典版本 1.9.0）。本次一起做了四件事：

1. **修掉一个会让汉化直接失败的官方包问题**：2.28.1 的 `app.asar` 索引里声明
   `node_modules/chrome-devtools-mcp/.../selectElementAccessibility…Descendant.md` 是外部文件（unpacked），
   但 `app.asar.unpacked` 目录下实际没有这个文件——官方打包漏了一个（1085 个条目里坏 1 个）。
   标准 asar 工具遇到「索引里有、文件却没有」的条目会整体报错退出，汉化在解包阶段就中止。
   现在工具内置了一个容错解包器：官方工具失败时自动接管，逐条处理、跳过缺失项并明确提示。
   跳过的文件本来就读不到，跳过不改变运行行为。
   打包后的完整性守卫也同步排除这 1 个条目——否则**「再跑一次汉化」会误报中止**
   （参照官方备份时发现缺这一项）。这个坑是实测踩到才发现的，两条入口都验证过：
   从官方原版跑、从已汉化状态重跑，产物字节完全一致。
2. **修掉 22 条中英混杂**：核心词表会把没被精确收录的新词逐词硬替换，产出
   `删除 All Data`、`添加 Shortcut`、`Cloud 项目`、`Empty 日志` 这类半截货，比纯英文更难受。
   这批全部补了精确词条，实测中英混杂从 49 条降到 9 条（剩下的是 GitHub / Google Sans / Chrome
   这类专有名词保留，属正常译法）。
3. **引擎加了技术串保护**（`engine.js` 的核心词分词环节）：原来 `\b` 词边界在 `/` `.` `-` `:` 旁边也算边界，
   会把 `https://policies.google.com/privacy` 里的词、`show-more` 这类连字符标识符一起替换掉，
   产出坏 URL 和坏标识符——这比不翻更危险。现在「无空格且含技术符号」的串直接原样返回。
   用 25006 条样本做新旧引擎对照：**误伤 0 条**，39 条译文由混杂变干净，51 条从不翻变成翻。
4. **旧词条一律保留，不删**：还在用旧版本的用户不受影响。

   这些老词条留在词典里既不会误翻、也不占运行时开销，保留是为了向后兼容旧版本，

4. **修掉 5 条历史错译**（这轮深度审计挖出来的）：`ID` 曾被译成"标题"、`URL` 译成"文件"、
   `PID` 译成"内存(MB)"、`For` 译成"适用源"、`uv` 译成"UV 包管理器"，
   都是早期合并上游词典时串行的。这几个是界面表头/状态字段，译错会让用户看到**错误信息**。
   缩写类（ID / URL / PID / uv）直接删条目保持英文——中文界面本来也写 ID、URL；
   `App` 则从"应用设置"改正为"应用"。

**这一版的覆盖率是怎么算的（可以自己复核）**：把 2.28.1 的真实界面包逐条提取，
得到 2466 条候选文案，用内置引擎实跑一遍：**2123 条已翻译（86.1%）**（v1.10 补漏后为 2164 条 / 87.8%）。

`[McpServerStates]` 等）、示例占位值（`Workspace_1`、`http://localhost:8080`、`my-gcp-project`）、
命令标识符（`run_command` / `view_file`）、LaTeX 渲染命令（`\fbox` / `\angl`），
另有 17 条路径与内部短链、5 条枚举常量、字体名与按键名各 1 条。
**这些刻意不翻**：翻协议错误串会破坏 MCP 通信，翻示例占位符会误导用户填错值，
翻模型名会让人认不出是哪个模型，翻 `ID`/`URL` 反而让人看不懂。它们不是"漏掉"，是"不该动"。

**v1.7 里的一个安全修复**：审计时发现 Antigravity 会把 `aria-label` 当作稳定标识使用
（例如某个输入框失焦时用 `aria-label === "Cancel"` 判断是否点了「取消」）。
此前引擎会翻译 `aria-label`，一旦译成「取消」，该判断失效——点取消反而会提交内容。
现已把 `aria-label` 移出翻译范围：它是给读屏软件的标识，不是可见文案，不翻不影响界面观感。

**v1.7 里的另外三处修复**（都是这轮深度审计挖出来的）：

1. **macOS「检查更新」菜单项点击失效**：官方代码用 `updateActions[menuItem.label]` 查动作表，
   键是英文；标签被翻成「检查更新」后查不到，点击静默无反应。现在保留英文原值用于查表，
   显示仍用译文；更新状态变化时也不会再变回英文。
2. **17 条词条错位**：英文讲的是 A，中文写的却是完全无关的 B
   （例如 `Model: {0}` 被写成「选择模型」、`Jetski Update Available` 被机翻成「摩托艇更新可用」）。
   这些是早期从上游词典合并时串行的历史遗留，本版逐条改正，并新增占位符一致性门禁防复发。
   （补充说明：经全安装目录比对，这些词条在 2.25.0 界面中并未被引用，属当前版本用不到的历史条目；
   本次修正属词典准确性维护，不会改变可见界面。）

### 刻意保留英文的内容（设计共识，不是遗漏）

| 内容 | 原因 |
|---|---|
| AI 思考过程（Thinking） | 流式推理内容不适合词典翻译，强行翻会夹生卡顿；正文/总结/计划是中文 |
| 模型名（Gemini、Claude 等） | 产品名，翻译会造成识别混乱 |
| 个别受控下拉选项 | 翻译会导致组件状态失配、界面卡死，以"能用"优先 |
| 代码与代码块 | 程序代码不该被翻译 |
| 你输入的内容 | 输入区物理隔离，永远不会动你打的字 |

## 常见问题

**Q：双击 `一键汉化.bat` 窗口一闪就没了？**
说明启动脚本本身出错了。在文件夹空白处按住 Shift 右键 →「在此处打开 PowerShell 窗口」，
然后执行 `python localize.py`，能看到完整报错。最常见的原因是没装 Python 或没勾 "Add Python to PATH"。

**Q：双击报 `'xxx' 不是内部或外部命令`？**
批处理文件被换行搞坏了（见「注意事项」第 10 条）。用 v1.8 的包，别用第三方编辑器改过的 bat。

**Q：汉化完了界面还是英文？**
先跑选项 `3` 看状态是不是"已汉化"，再确认完全退出 Antigravity（含托盘图标）后重新打开。
运行时 DOM 翻译依赖界面加载完成，第一次打开稍等 1～2 秒。

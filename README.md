## 这是什么

[Antigravity](https://antigravity.google) 是 Google 出品的智能体编程 IDE，界面默认英文。
本工具把它完整变成简体中文——不需要懂命令行，不需要会编程：

- **双击 `一键汉化.bat`（Windows）/ `一键汉化.command`（macOS）/ 运行 `一键汉化.sh`（Linux）**，按数字选功能
- 官方更新后界面变回英文？**再双击一次，重新汉化就好**
- 想换回英文原版？**一键还原**，还原结果与官方原版字节级一致

## 使用方法

### 环境要求

> [!IMPORTANT]
> **Node.js 是可选的，不装也能汉化。**
> v1.17.1 起工具会自动识别：
> - **装了且能正常启动** → 对改完的文件逐个跑 `node --check`，做**语法级**校验（最严格）
> - **没装，或装了但启动不起来** → 自动改用**结构自检**（注入块是否成对、文件是否完整），汉化照常完成
>
> v1.19.1 起「能不能启动」是**实测**的：只确认 PATH 里有这个名字不够——
> 有些机器残留着失效的 `node.cmd` 包装脚本或卸载后的执行别名，旧版会误判成可用，
> 然后**每个被修改的文件都报一次**「语法校验失败」，看着像工具坏了，其实原文件一个字节都没动。
>
> **两种情况下翻译内容完全一样**——Node.js 只负责"改完的代码语法对不对"这一步检查，
> 不参与翻译。区别只在「万一改坏了能不能当场发现」。
> **真正必需的是 Python 3.8+。**

**Windows：**

- Windows + 已安装 Antigravity（默认安装路径自动识别，装在别处可用 `--path` 指定）
- [Python](https://www.python.org/downloads/) 3.8+（安装时勾选 **Add Python to PATH**）—— **必需**
- [Node.js](https://nodejs.org) 18+ —— **可选**。装了会做语法级校验；
  没装则自动走结构自检。`npx` 也只用于官方 asar 工具，
  没有 Node.js 时直接用内置打包器（**全程离线**）

**macOS**（详见 [mac/README.md](https://github.com/QingniaoDawn/Antigravity-YiJianHanHua/blob/main/mac/README.md)）：

- macOS 12+ + 已安装 Antigravity
- Python 3.8+（`brew install python`）—— **必需**
- Node.js 18+（`brew install node`）—— **可选**，同上
- **Xcode 命令行工具**（`xcode-select --install`）——提供 `codesign`/`xattr`，
  没有它汉化后 App 会打不开，主程序会在汉化前明确报错

**Linux**（详见 [linux/README.md](https://github.com/QingniaoDawn/Antigravity-YiJianHanHua/blob/main/linux/README.md)）：

- Linux x86_64 + 已安装 Antigravity
- Python 3.8+（多数发行版自带；没有就用包管理器装）—— **必需**
- Node.js 18+ —— **可选**，同上
- 若 Antigravity 装在 `/opt` 或 `/usr/lib` 这类需要 root 的目录，
  脚本会在最后落盘那一步弹出 `sudo`/`pkexec` 授权（前面所有工序都在临时目录以普通用户完成）

### 操作菜单

Windows 双击 `一键汉化.bat`，macOS 右键 `一键汉化.command` →「打开」，
Linux 在终端执行 `./一键汉化.sh`：

| 选项 | 功能 |
|---|---|
| `1` 一键汉化 | 自动关进程 → 备份原版 → 注入汉化 → 校验 → 部署（macOS 追加自动重签名）→ 对话标题中文化（macOS 额外重签该二进制） |
| `2` 恢复官方英文原版 | 用备份一键还原，字节级与官方一致（对话标题补丁一并回滚） |
| `3` 查看状态 | 当前是否已汉化、备份是否完好、对话标题生成器状态（macOS 追加签名健康度） |
| `4` AI 回复中文化 | 写入一条全局规则，让 **AI 自己用中文回答**（思考过程仍英文，可随时关闭） |
| `5` 检查更新 | 查 GitHub 上有没有新版本；可选下载到桌面，**不会自动替换你现有的文件** |

也可以命令行调用：`python localize.py apply / restore / status / chinese-output / update`（macOS 用 `python3`）

### 关于「插件界面汉化」（会动 `~/.gemini`，请先看这段）

「智能体集群」这类**内置插件**不是网页界面，而是独立的小应用（sidecar），通过 `plugin://` 在隔离的 iframe 里加载。浏览器的同源策略让主界面的翻译引擎够不到它的文档，所以只能直接改插件自己的界面文件。

| 项目 | 说明 |
|---|---|
| **改哪里** | `~/.gemini/antigravity/builtin/plugins/<插件名>/sidecars/` 下的 HTML 与 JS |
| **改之前** | 每个文件先存一份同名 `.agyzhbak` 备份，备份成功才动原文件 |
| **怎么还原** | 菜单 `2`「恢复官方英文原版」会把它们一起还原，并删掉备份 |
| **官方更新后** | 插件更新会覆盖这些文件（界面变回英文），重跑一次汉化即可恢复 |
| **改了什么** | 只替换界面文字的字符串，不动任何逻辑；改完逐个做语法校验，不合格就回滚 |
| **没装这个插件** | 目录不存在时自动跳过，不会有任何副作用 |

> 目前**没有单独的开关**可以只汉化主界面、不动插件。如果你不希望任何文件被改动，请先不要运行本工具。

### 关于「检查更新」

- **默认不联网**：只有你主动选 `5`（或运行 `update`）时才会发一次请求，
  其余所有功能（汉化、还原、查看状态、AI 中文化）全程零网络行为。
- **只查不换**：请求的是 GitHub Release 元数据（版本号、更新说明、下载链接），
  不下载执行任何远端代码。就算你选了下载，也只是把 zip 存到桌面，
  **解压和替换由你自己决定**，本工具绝不动你现有的文件。
- **下不动有退路**：可以选「只要下载链接」，自己用浏览器或下载工具下。
- **查不到不影响使用**：网络不通、被限流时只会提示一句，不会报错卡住。
- **带 SHA256 校验**：若该版本的 Release 附带了 `SHA256SUMS.txt`，下载后会自动比对，
  不一致会明确告警，让你知道文件可能不完整或被掉包。

> **想让 AI 的回复也是中文？** 选 `4`。界面汉化管不了 AI 生成的内容，
> 正确做法是加一条"用简体中文回复"的全局规则（脚本已内置该功能）。

### 官方更新后怎么办

Antigravity 官方更新后界面会变回英文——这是正常现象，不是坏了。
**再运行一次选项 `1` 重新汉化即可**，备份会自动升级为新版官方原版。

**macOS 特别注意**：Mac 的更新组件在安装新版前会校验「当前 App 的代码身份」，
真正替换文件时还要靠 App 内的 `ShipIt` 安装器。重签时这两处会一并处理，
日志与「查看状态」会如实显示更新能力；如果显示不可用，请从官网下载新版覆盖安装，再重新汉化。
详细机制见 [mac/README.md](https://github.com/QingniaoDawn/Antigravity-YiJianHanHua/blob/main/mac/README.md#q重签名会不会影响我以后更新-antigravity)。

**可以连续操作**：每个操作做完会停一下让你看结果，按回车就回到主菜单，接着选下一项即可
（比如先「查看状态」再「一键汉化」，或者「汉化 → 恢复英文 → 再汉化」）。
窗口不会自己关掉；要关闭请点右上角的 ×，或者选 `0` 退出。
（macOS 上重签名也会一并重新完成）

- **权限确认弹窗**：一直允许 / 仅允许一次 / 拒绝 / 跳过 等全套按钮

### 刻意保留英文的内容（设计共识，不是遗漏）

| 内容 | 原因 |
|---|---|
| AI 思考过程（Thinking） | 流式推理内容不适合词典翻译，强行翻会夹生卡顿；正文/总结/计划是中文 |
| 模型名（Gemini、Claude 等） | 产品名，翻译会造成识别混乱 |
| 个别受控下拉选项 | 翻译会导致组件状态失配、界面卡死，以"能用"优先 |
| 代码与代码块 | 程序代码不该被翻译 |
| 你输入的内容 | 输入区物理隔离，永远不会动你打的字 |
| 会话标题 / 项目名 / 侧问标签 | 这些是**你自己起的名字**（双击即可改名），翻译等于改你的数据；窗口标题同理，保持你原本写的语言。注意这条只管「翻译」，不管「生成」——模型新生成的标题走另一条路，见下一节 |

### 对话标题为什么会是英文，本工具怎么处理

左侧会话列表的「对话名称」和长对话的「章节标题」不是界面元素，而是后台
`resources/bin/language_server` 进程调云端模型**现场总结**出来的。它用的是自己内部
硬编码的提示词，不读 `~/.gemini/config/rules/` 里的用户规则，而且原文把英文写死在里面：

- 对话标题：`Respond with ONLY a short conversation title (3-5 words, title-cased, no prefix)`
- 章节标题：`Reply with only a plain 3 to 6 word title in sentence case, ...`

所以你全程用中文提问，标题照样是英文 Title Case。本工具把这两段提示词换成要求输出
简体中文的版本：两段原文分别是 214 和 238 字节，替换文本**一字节不差地保持同样长度**，
二进制里的段偏移、符号表、字符串长度头因此全部原样不变——文件大小不变、零运行时开销，
`--help` 输出与官方逐字节一致。

## 常见问题

**Q：双击 `一键汉化.bat`，窗口一闪就没了 / 按任意键就闪退？**

v1.12 起的包不会再静默关窗：无论成功、出错还是中途取消，窗口都会停住并写明原因。
如果你手上是旧包，或者新版仍然遇到，按这个顺序查：

1. **先看窗口最底部有没有停住不动**。有，说明脚本已经跑完了，
   窗口是在等你按键确认，不是崩溃——往上翻就能看到它做了什么。
2. **看目录里有没有 `hanhua_error_log.txt`**。有就直接发给作者：里面记了系统版本、
   Python 版本、解释器路径和完整错误，不需要你再描述电脑环境。
   （这份日志会带上你的电脑用户名和安装路径，要公开发到论坛前先自己扫一眼。）
3. **想看完整报错**：在文件夹空白处按住 Shift 右键 →「在此处打开 PowerShell 窗口」，
   执行 `python localize.py`（找不到 python 就换 `py -3 localize.py`）。

> 注意：锁冲突（重复双击）和"你主动取消"不会生成这个日志，别去找它。

最常见的三个原因：

- 没装 Python，或安装时没勾 **Add Python to PATH**；
- Python 版本低于 3.8；
- 杀毒软件拦截了脚本（见「注意事项」第 1 条）。

> **Node.js 不在其中**：从 v1.17.1 起它已经是可选项，缺了不会中止，
> 工具会自动改用内置结构自检继续完成汉化。

> **启动脚本为什么是英文？**
> `一键汉化.bat` 刻意保持纯 ASCII，一行中文都不放。原因是 cmd 会按**控制台代码页**
> 解码 bat 文件：在英文版 Windows（代码页 437）下，GBK 汉字的第二个字节可能正好是
> `|` 或 `^`，cmd 会把它当管道/转义符，把整行截断后把后半截当命令执行——
> 实测会出现一堆 `xxx is not recognized as an internal or external command`。
> 所以 bat 只管启动和兜底，**所有中文提示都由 `localize.py` 输出**：
> Python 走 `WriteConsoleW` 宽字符通道，和代码页无关，中文版、英文版、UTF-8 模式
> 三种系统下都验证过，显示完全一致。

**Q：双击报 `'xxx' 不是内部或外部命令`？**
批处理文件被换行搞坏了（见「注意事项」第 10 条）。用最新版的包，
别用第三方编辑器改过 bat。

**Q：汉化完了界面还是英文？**
先跑选项 `3` 看状态是不是"已汉化"，再确认完全退出 Antigravity（含托盘图标）后重新打开。
运行时 DOM 翻译依赖界面加载完成，第一次打开稍等 1～2 秒。

**Q：卡在「正在重新打包 app.asar」并报 `npm error errno: 'EPERM'`？**
不是工具坏了，是那台机器的 **npm 缓存目录写不进去**。`npx` 在下载工具之前要先往缓存里
落临时文件，目录没权限就直接 `EPERM` 退出，还会甩一屏 npm 内部栈（典型现场：缓存被设到
`C:\某目录\node_cache`，而这个目录是管理员装的、或整个从别的账户拷过来的）。

工具现在会在开工前先探测一次缓存目录：写不进去就打印修复办法，并**自动改用内置打包器**
（带逐文件字节校验）把汉化做完，不再卡死。想让 `npx` 也恢复正常，在 **cmd** 里执行一次
（不需要管理员权限，缓存会搬回 npm 的默认位置）：

```bat
npm config set cache "%LOCALAPPDATA%\npm-cache"
```

⚠️ 这条别贴到 PowerShell：那里的 `%LOCALAPPDATA%` 不会展开，会存成一个无效路径。

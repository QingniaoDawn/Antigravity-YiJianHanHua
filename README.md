## 这是什么

[Antigravity](https://antigravity.google) 是 Google 出品的智能体编程 IDE，界面默认英文。
本工具把它完整变成简体中文——不需要懂命令行，不需要会编程：

- **双击 `一键汉化.bat`（Windows）/ `一键汉化.command`（macOS）**，按数字选功能
- 官方更新后界面变回英文？**再双击一次，重新汉化就好**
- 想换回英文原版？**一键还原**，还原结果与官方原版字节级一致

## 使用方法

### 环境要求

**Windows：**

- Windows + 已安装 Antigravity（默认安装路径自动识别，装在别处可用 `--path` 指定）
- [Python](https://www.python.org/downloads/) 3.8+（安装时勾选 **Add Python to PATH**）
- [Node.js](https://nodejs.org) 18+（`node` 用于改完 JS 后的语法门禁，是硬要求；
  `npx` 只用于官方 asar 工具——npm 缓存写不进去时会自动改用内置打包器，不影响汉化）

**macOS**（详见 [mac/README.md](mac/README.md)）：

- macOS 12+ + 已安装 Antigravity
- Python 3.8+（`brew install python`）
- Node.js 18+（`brew install node`）
- **Xcode 命令行工具**（`xcode-select --install`）——提供 `codesign`/`xattr`，
  没有它汉化后 App 会打不开，主程序会在汉化前明确报错

### 操作菜单

Windows 双击 `一键汉化.bat`，macOS 右键 `一键汉化.command` →「打开」：

| 选项 | 功能 |
|---|---|
| `1` 一键汉化 | 自动关进程 → 备份原版 → 注入汉化 → 校验 → 部署（macOS 追加自动重签名） |
| `2` 恢复官方英文原版 | 用备份一键还原，字节级与官方一致 |
| `3` 查看状态 | 当前是否已汉化、备份是否完好（macOS 追加签名健康度） |
| `4` AI 回复中文化 | 写入一条全局规则，让 **AI 自己用中文回答**（思考过程仍英文，可随时关闭） |
| `5` 检查更新 | 查 GitHub 上有没有新版本；可选下载到桌面，**不会自动替换你现有的文件** |

也可以命令行调用：`python localize.py apply / restore / status / chinese-output / update`（macOS 用 `python3`）

### 关于「检查更新」

- **默认不联网**：只有你主动选 `5`（或运行 `update`）时才会发一次请求，
  其余所有功能（汉化、还原、查看状态、AI 中文化）全程零网络行为。
- **只查不换**：请求的是 GitHub Release 元数据（版本号、更新说明、下载链接），
  不下载执行任何远端代码。就算你选了下载，也只是把 zip 存到桌面，
  **解压和替换由你自己决定**，本工具绝不动你现有的文件。
- **下不动有退路**：可以选「只要下载链接」，自己用浏览器或下载工具下。
- **查不到不影响使用**：网络不通、被限流时只会提示一句，不会报错卡住。
- **带 SHA256 校验**：若该版本的 Release 附带了 `SHA256SUMS.txt`，下载后会自动比对，
  不一致会明确告警，让你知道文件可能不完整或被掉包。

> **想让 AI 的回复也是中文？** 选 `4`。界面汉化管不了 AI 生成的内容，
> 正确做法是加一条"用简体中文回复"的全局规则（脚本已内置该功能）。

### 官方更新后怎么办

Antigravity 官方更新后界面会变回英文——这是正常现象，不是坏了。
**再运行一次选项 `1` 重新汉化即可**，备份会自动升级为新版官方原版。

**可以连续操作**：每个操作做完会停一下让你看结果，按回车就回到主菜单，接着选下一项即可
（比如先「查看状态」再「一键汉化」，或者「汉化 → 恢复英文 → 再汉化」）。
窗口不会自己关掉；要关闭请点右上角的 ×，或者选 `0` 退出。
（macOS 上重签名也会一并重新完成）

界面翻译采用**运行时 DOM 文本匹配**，不修改官方界面文件本身。
因此官方更新不会破坏已有汉化，只可能新增少量未收录的新文案。

**v1.14（2026-11-13）**：修掉**右键菜单整块保持英文**的问题。上一版把界面翻得差不多了，
但只要在对话列表、消息气泡、标签页上点右键，弹出来的仍是
`Copy Message` / `Undo to Here` / `Rename` / `Pin` / `Mark Unread` / `Split` / `Archive` / `Delete`。

**根因不是漏词条，是渲染通路压根不同**。右键菜单走的是原生菜单：
渲染进程把菜单项压成 `{id,label,type,checked,disabled,accelerator}`（顺带**丢掉图标**），
经 `window.electronNative.showContextMenu` → IPC `window:show-context-menu` →
主进程 `Menu.buildFromTemplate` → 操作系统弹窗。**它不产生任何 DOM 节点**，
所以 preload 里的 DOM 引擎（MutationObserver）从头到尾看不到它。

三条实测证据：

1. 右键后 DOM 里 `.agy-overlay` 数量为 **0**，屏幕上却确实弹出了菜单；
2. 弹窗里的菜单项**没有图标**、快捷键右对齐——正是 `xYa()` 把 icon 丢掉后的形状；
3. 把包里 511 条菜单标签逐条比对词典：**482 条早就收录了**（大小写不敏感兜底），
   其中就包括用户截图里的 `Copy Message` / `Rename` / `Pin` / `Mark Unread` / `Archive` / `Delete`。
   漏的只有 `Undo to Here` 等极少数——说明问题不在词条。

**修法**：在 preload 暴露 `electronNative` 之前包一层，只翻译 `label`，
`id` / `disabled` / 点击回调 / 快捷键一律原样透传（主进程正是靠 `id` 回传选中项）。
几个关键设计：

- **深拷贝一层再改**：同一份 `items` 数组还可能被网页版菜单复用，原地改会污染调用方；
- **标签专用严格管道**：只走「精确 / 大小写 / 空白归一 / 尾标点 / 动态正则」，
  **不做核心词逐词替换**——否则会输出「复制 Trajectory ID」这类中英混杂；
- **失败即降级**：引擎缺失或抛异常时返回原文，宁可英文也不能让右键菜单失灵。

**词典同步**：新增 3 条精确词条（`Cog Workspace`、`Pin Tab`、`Unpin Tab`）、
12 条动态正则（`Delete <类型>`、`xxx (Remote)`、`xxx (Experimental)`、`xxx on this computer`、
`Detached at <sha>`、`Keep: xxx`、`Move to Group: xxx`、`Search Google for "xxx"`、
`Send feedback as xxx`、`Open <域名>`），修正 1 条历史混杂译文（`Copy trajectory ID`），
并把 `Undo To Here` 统一为「撤销到此处」。

**验证**：新增 61 项单测（菜单项逐条译文、结构透传、原数组不被修改、降级、幂等）全绿；
结构回归 **57/57 锚点**、语法门禁 0 失败、二次注入 0 增长；真机重启后逐项截图核对——
会话菜单「重命名 / 置顶（Alt+Shift+P）/ 标记为未读 / 复制 / 分屏 / 归档（Alt+Ctrl+A）/ 删除」、
消息菜单「复制消息 / 撤销到此处 / 19 分钟前」、选中文字菜单「复制」全部中文；
点击「置顶」后 `data-pinned` 由 `false` 变 `true`，说明翻译没有影响菜单功能。

**同一版补掉的两个尾巴**：

1. **内置浏览器「无边框弹窗」的右键菜单**。它走的是另一条原生菜单
   （`dist/webviewPopupSecurity.js` 的 `contents.on('context-menu')`），之前整块是英文。
   已在 `staticPatches` 里加了 20 条锚点：菜单四项改为 `{role, label}` 形式（**动作靠 role 不变**）、
   「连接信息…」、对话框标题与确定按钮、证书详情字段（颁发给 / 颁发者 / 生效时间 / 到期时间 / 协议）、
   安全摘要五句、标题栏「不安全」标记。离线跑真实模块验证 21 项全过。
2. **用户消息右上角的时间戳**（`37m ago`）。它挂在 `user-input-step` 子树里，
   而引擎为了保护用户原文会把整棵子树剪掉——子节点的白名单根本没机会执行。
   现在改成在剪枝处单独把 `[data-testid="user-message-actions"]` 这块捞出来翻译，
   用户正文仍然受保护。真机验证：`37m ago` → `37 分钟前`。

**刻意保留英文**：28 条 label 仍保持原文（含空串、标点、代码片段）——模型名（`Flash`、`Pro`、
`Gemini Flash Next`）、产品名（`GitHub`、`Google Chat`、`Drive`、`MCP`）、系统名（`Windows` / `macOS` / `Linux`）、
代码片段与 URL。菜单里动态拼接的文件名、工作区名同样保持原样——翻译它们只会让人认不出是哪个文件。

**v1.12（2026-11-05）**：修「打开后按任意键就闪退」。

先说结论：**不是 Antigravity 崩溃，是启动脚本收尾时不给你看结果**。
旧版有三条路径会让窗口瞬间消失——跑完直接关窗、按 Ctrl+C 被当成"成功"、报错后退出码被误判。
现在无论成功、出错还是中途取消，窗口都会停住并写明原因，退出时还会补一句
「这是正常结束，不是闪退」。

- **启动脚本改成纯 ASCII**：cmd 按控制台代码页解码 bat，英文版 Windows（代码页 437）下
  GBK 汉字的第二字节可能落在 `|` 或 `^` 上，cmd 会当控制符把整行截断。
  现在 bat 里一个中文字都不放，中文全部由 `localize.py` 输出（走 `WriteConsoleW` 宽字符通道，
  与代码页无关）。437 / 936 / 65001 三种代码页实测显示完全一致。
- **失败自动留证据**：出错会写 `hanhua_error_log.txt`，含系统版本、Python 版本、解释器路径、
  完整错误。但锁冲突（重复双击）和你主动取消不会写，免得误以为程序坏了。
- **错误翻成人话**：文件被占用不再是 `WinError 32`，而是「Antigravity 没退干净或杀软在扫描，
  本次没有改动你的软件，可以放心重试」；权限不足会提示用管理员身份运行。
- **`--path` 更宽容**：现在直接拖 `Antigravity.exe` 或 `app.asar` 进去也能正确识别。
- **压缩包误用有提示**：直接在 zip 里双击 bat，会明确告诉你「请先完整解压」。
- 顺手修了 macOS 版收尾：原来成功时直接 `exit 0`，Terminal 若设了「退出即关窗」同样一闪而过。

**v1.11（2026-11-02）**：这一版不碰词典，修的是**装不上/跑不完**的两处硬伤。
起因是有人反馈汉化卡在「正在重新打包 app.asar」，报 `npm error errno: 'EPERM'`：

- **打包不再依赖 npx**：原来解包有内置降级、打包却只有 `npx @electron/asar` 一条路，
  所以那台机器（npm 缓存目录没有写权限）跑到最后一步必死，而且前面所有步骤都白跑。
  现在补了纯 Python 的 asar 打包器，产物与官方工具**逐字节一致**
  （2.28.2 实测：8,236,626 字节 sha256 完全相同；中文名 / emoji / 特殊字符 / 空文件 /
  空目录 / 大文件分块等边界样本同样一致）。打包后还会把新包读回来逐文件比对
  sha256，对不上就中止，绝不部署没核对过的包。
- **开工前先探 npm 缓存**：缓存目录不可写就直接打印中文修复办法
  （`npm config set cache "%LOCALAPPDATA%\npm-cache"`），并把本次全程切到内置工具链，
  不再让 npx 甩一屏英文栈、也不再把失败藏到最后一步。
- `node` 仍是硬要求（改完 JS 要做语法门禁），`npx` 降为可选。
- 另外把 README 里「零联网」的说法改准了：走 `npx` 时首次会取一次官方打包工具（约 3 MB），
  走内置打包器则完全本地。之前那句话不够准确，这次一并纠正。

   这些老词条留在词典里既不会误翻、也不占运行时开销，保留是为了向后兼容旧版本，
   方便还在用 2.24 / 2.25 的用户。

   都是早期合并上游词典时串行的。这几个是界面表头/状态字段，译错会让用户看到**错误信息**。
   缩写类（ID / URL / PID / uv）直接删条目保持英文——中文界面本来也写 ID、URL；

### 刻意保留英文的内容（设计共识，不是遗漏）

| 内容 | 原因 |
|---|---|
| AI 思考过程（Thinking） | 流式推理内容不适合词典翻译，强行翻会夹生卡顿；正文/总结/计划是中文 |
| 模型名（Gemini、Claude 等） | 产品名，翻译会造成识别混乱 |
| 个别受控下拉选项 | 翻译会导致组件状态失配、界面卡死，以"能用"优先 |
| 代码与代码块 | 程序代码不该被翻译 |
| 你输入的内容 | 输入区物理隔离，永远不会动你打的字 |

## 常见问题

**Q：双击 `一键汉化.bat`，窗口一闪就没了 / 按任意键就闪退？**

v1.12 起的包不会再静默关窗：无论成功、出错还是中途取消，窗口都会停住并写明原因。
如果你手上是旧包，或者新版仍然遇到，按这个顺序查：

1. **先看窗口最底部有没有停住不动**。有，说明脚本已经跑完了，
   窗口是在等你按键确认，不是崩溃——往上翻就能看到它做了什么。
2. **看目录里有没有 `hanhua_error_log.txt`**。有就直接发给作者：里面记了系统版本、
   Python 版本、解释器路径和完整错误，不需要你再描述电脑环境。
   （这份日志会带上你的电脑用户名和安装路径，要公开发到论坛前先自己扫一眼。）
3. **想看完整报错**：在文件夹空白处按住 Shift 右键 →「在此处打开 PowerShell 窗口」，
   执行 `python localize.py`（找不到 python 就换 `py -3 localize.py`）。

> 注意：锁冲突（重复双击）和"你主动取消"不会生成这个日志，别去找它。

最常见的三个原因：

- 没装 Python，或安装时没勾 **Add Python to PATH**；
- 没装 Node.js（改完 JS 要做语法校验，缺了会直接中止）；
- Python 版本低于 3.8。

> **启动脚本为什么是英文？**
> `一键汉化.bat` 刻意保持纯 ASCII，一行中文都不放。原因是 cmd 会按**控制台代码页**
> 解码 bat 文件：在英文版 Windows（代码页 437）下，GBK 汉字的第二个字节可能正好是
> `|` 或 `^`，cmd 会把它当管道/转义符，把整行截断后把后半截当命令执行——
> 实测会出现一堆 `xxx is not recognized as an internal or external command`。
> 所以 bat 只管启动和兜底，**所有中文提示都由 `localize.py` 输出**：
> Python 走 `WriteConsoleW` 宽字符通道，和代码页无关，中文版、英文版、UTF-8 模式
> 三种系统下都验证过，显示完全一致。

**Q：双击报 `'xxx' 不是内部或外部命令`？**
批处理文件被换行搞坏了（见「注意事项」第 10 条）。用最新版的包，
别用第三方编辑器改过 bat。

**Q：汉化完了界面还是英文？**
先跑选项 `3` 看状态是不是"已汉化"，再确认完全退出 Antigravity（含托盘图标）后重新打开。
运行时 DOM 翻译依赖界面加载完成，第一次打开稍等 1～2 秒。

**Q：卡在「正在重新打包 app.asar」并报 `npm error errno: 'EPERM'`？**
不是工具坏了，是那台机器的 **npm 缓存目录写不进去**。`npx` 在下载工具之前要先往缓存里
落临时文件，目录没权限就直接 `EPERM` 退出，还会甩一屏 npm 内部栈（典型现场：缓存被设到
`C:\某目录\node_cache`，而这个目录是管理员装的、或整个从别的账户拷过来的）。

工具现在会在开工前先探测一次缓存目录：写不进去就打印修复办法，并**自动改用内置打包器**
（带逐文件字节校验）把汉化做完，不再卡死。想让 `npx` 也恢复正常，在 **cmd** 里执行一次
（不需要管理员权限，缓存会搬回 npm 的默认位置）：

```bat
npm config set cache "%LOCALAPPDATA%\npm-cache"
```

⚠️ 这条别贴到 PowerShell：那里的 `%LOCALAPPDATA%` 不会展开，会存成一个无效路径。
